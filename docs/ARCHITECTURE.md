# AZ Studio architecture

## Isolation inside the shared `az-learner` project

The Firebase project also hosts other apps (Hosting sites `az-learner`/“Last Hour”, `absag-ucc1`, `cv-build`, `hallkey`, `orglet`, `tmg-22`; several Firestore databases; the `absag*` functions). AZ Studio therefore uses only its own resources:

| Resource | Name |
| --- | --- |
| Hosting site | `az-studio` → https://az-studio.web.app |
| Web app | `AZ Studio` (`1:12958795950:web:06bec3bbdd07bc1c40453f`) |
| Firestore database | `az-studio` (us-central1, delete protection on) |
| Storage bucket | `az-studio-media-az-learner` (us-central1, uniform access, public access prevention) |
| Functions codebase | `az-studio` (`azsApi`, `azsJobWorker`, `azsOnUpload`, `azsMaintenance`) |
| Cloud Run jobs | `az-studio-renderer` (FFmpeg + libass, real font metrics), `az-studio-stems` (Demucs) |
| Service accounts | `az-studio-api@` (functions), `az-studio-renderer@` (render job) |
| Secrets | `AZ_STUDIO_OWNER_UID`, `AZ_STUDIO_OWNER_EMAIL`, `AZ_STUDIO_GEMINI_API_KEY` (Lyria 3.5 on the Gemini Developer API; optional) |
| API key | `AZ Studio Web (restricted)` — referrer-restricted to AZ Studio domains |
| App Check | reCAPTCHA Enterprise key `AZ Studio App Check` |

The default Firestore database, the default bucket and their rules are **not** touched by AZ Studio deploys.

## Request flow

```
Browser (Auth + App Check) ──callable──▶ azsApi (owner check, zod + capability validation, cost/limits)
                                            │ writes jobs/{id}, enqueues Cloud Task
                                            ▼
                                   azsJobWorker (Cloud Tasks, idempotent, leases)
          ┌──────────────┬────────────────────┼────────────────────┬─────────────────────┐
   Nano Banana Pro   Gemini Omni (Interactions   Gemini Pro (JSON)   Cloud Run job (FFmpeg)
   generateContent   API, background + poll)     writing / song AI    renders timelines
          └──────────────┴──── media → private bucket, assets/{id}, usage records ─────────┘
Browser ◀── Firestore listeners (jobs, assets, renders) ── signed URLs (2 h) for playback
```

- **Durable jobs.** Status `queued → validating → generating → downloading → rendering → completed | failed | cancelled` (see `packages/shared/src/jobs.ts`). Every Cloud Tasks delivery is idempotent: jobs are claimed with a lease, Omni interactions are polled by re-enqueued tasks, and `azsMaintenance` re-attaches lost pollers or fails jobs whose worker died *without* resending paid requests.
- **Omni chains.** Every video result is stored with `store: true`; follow-up edits and extensions reference the parent turn server-side (`previous_interaction_id`) and carry no `generation_config.video_config.task` — Vertex AI rejects a task alongside a previous interaction, so the prompt states the change. An extension returns the whole video (e.g. 4 s + 4 s → 8 s) but is billed for the new seconds, with the earlier video as input (verified 2026-09-24). After the retention window the server re-sends the prior clip (≤10 s) with the `edit`/`extend` task instead; Omni refuses to change or continue speech in a re-sent clip, so dialogue repairs only continue live interactions and otherwise regenerate.
- **No fabricated parameters.** Requests are validated against `VIDEO_CAPABILITIES` / `IMAGE_CAPABILITIES`; unset options are omitted. Camera, lighting, mood, dialogue and sound are compiled into prompt text, not sent as API fields.
- **Audio.** Omni does not accept audio input. Songs are analysed in the browser (beats, tempo, sections; `packages/shared/src/audio.ts`) and by Gemini Pro (section labels, lyric transcription); timing becomes prompt directions and the real track is mixed by the renderer.
- **Upload validation.** `azsOnUpload` sniffs magic bytes, then probes audio/video with ffprobe and derives posters and waveforms with ffmpeg. The bundled static binaries crash when they resolve a hostname in the Cloud Functions runtime, so they read Storage objects through a loopback range proxy (`functions/src/lib/media-proxy.ts`) instead of signed URLs; large files are streamed by range, never downloaded whole.
- **Rendering.** The renderer splits the timeline into segments that never cut through transitions, renders each (overlays, transitions, Ken Burns, libass captions), concatenates losslessly, mixes audio once (loudness-normalised for final), muxes with `+faststart`, and writes a `provenance.json` sidecar.
- **Provenance.** Generated originals are stored byte-for-byte (C2PA manifests preserved and detected); SynthID is inherent to the pixels/audio. Re-encoded renders cannot keep source C2PA manifests — the sidecar lists each source’s status.

## Quality-controlled production

A production (`productions/{id}`) is a durable state machine driven by Cloud Tasks `advance` payloads (`functions/src/lib/production.ts`); child jobs carry `productionId`, and every terminal job transition re-enqueues the production. Statuses: Planning → Generating → Inspecting → Repairing → Awaiting review → Approved, or Failed quality review (plus Awaiting repair approval when a retry would pass the cost ceiling or is expensive). Stages: `plan`, `audio_prepare`, `duration_calculate`, `generate`, `inspect`, `repair`, `reinspect`, `approve`, `render`. Every version, report, repair and event is stored under the production.

- **Duration is a preference.** `packages/shared/src/duration.ts` computes the required length from the dialogue (guide audio spoken by `gemini-2.5-pro-tts` and measured with FFmpeg, uploaded recordings, or lines identified in an inspected take), speaker pauses, action beats, an opening (0.4–1 s) and closing hold (0.8–1.5 s). A scene that does not fit is lengthened, or produced as connected Omni extensions that break only at sentence boundaries (≤ 40 s), or split into separate shots. Omni cannot take audio input, so the guide audio is used for measurement and timing directions; the delivered dialogue is verified after generation.
- **Inspection** (`functions/src/workers/inspect.ts`) measures the real file (speech bounds, trailing room, clipping, loudness, scene cuts, black frames, end motion), transcribes it with word timestamps (`gemini-3.5-transcribe-preview`), aligns the transcript to the screenplay (`packages/shared/src/text-align.ts`: missing, altered, repeated, truncated words, early/late start, cutoff time), and has `gemini-4-argon` watch the video with the reference images for the scene review (speaker attribution, lip-sync, action beats, continuity, artefacts, first/last frames, scores) and the continuity director (characters, set, blocking, direction, text, props, temporal faults, edges, detected state, 15 category scores). The 32-section schema goes in the prompt (JSON mode): Gemini refuses it as a response schema (too complex to enforce), and enforcing it in parts made the scores collapse to flat, unexplained values. Every reply is checked against the schema before anything is scored; an incomplete or mistyped reply fails the inspection (retried) instead of being read with default values. The verdict (`evaluateQuality`) is deterministic: incomplete dialogue caps the score at 55, incomplete action at 60, critical faults at 40; a failing version can only be approved through the API with the waived issues recorded. Picture cuts are checked against the plan: joins between connected shots and the reaction-shot / reverse-angle cuts a continuation part was directed to make (up to two per part) are intended; any other cut is reported, and fails the scene when the reviewer also sees it.
- **Repair** (`chooseRepair`) escalates from the least destructive fix: trim a spoiled ending → extend the scene (Omni extension) → Omni conversational edit → cutaway → regenerate a failed section → regenerate longer / split into connected shots. Defaults: 3 automatic attempts, $6 cost ceiling per production, approval required for retries above $1.50.

## Short Ads

A short ad is a project of type `short_ad`; its draft (`project.ad`, `packages/shared/src/ads.ts`) is saved from the browser shortly after every edit. Scenes are shots carrying an `ad` spec; the narration transcript is a song's lyric sheet, so captions reuse the lyric styles and sync checks.

- **Audio-first.** The uploaded audio's server-measured duration is the length of the advert. `narration.transcribe` transcribes it with word timestamps (protected terms such as *Kasem* and *Indigen World* as custom vocabulary) and reconciles the result with the approved script, which is a reference only: script spelling is used where the recording plainly says a word (protected terms keep their spelling), words the recording lacks are reported, never captioned as heard.
- **Storyboard.** Scene windows are planned from the narration (cuts just before a sentence's first word) and must tile the audio exactly; a generated scene is at most one generation long (10 s). Kinds: generated video or still, product screen, supplied footage or photo, typography, end card.
- **Generation.** `adGenerate` creates requests only for generated scenes without a usable take, behind a per-scene lock (no double submission); completed scenes are never regenerated unless named. Every take is validated (`ad.validate`: decode, duration — clips are never stretched — aspect, resolution, black frames and a review against the brief; another brand's readable name, logo or watermark fails the take) with at most `generation.qualityRepairs` automatic regenerations per scene.
- **Composition.** `assembleAdTimeline` cuts scenes on their windows, places product screens and the logo in boxes on the brand colour (`Clip.layout`), composes typography and the end card as text, adds narration captions (sentences in typography scenes and the end card switch to large, restrained type) and lays the approved audio once, untouched. Renders use `audioMaster: 'preserve'` (no loudness normalisation, limiter or fades); final renders pass the export gate.

## Film Studio Lite

Narrated films of several minutes made from still images, slow camera movement, voice, subtitles, music and ambience (project type `film_lite`, sidebar → Film Lite, `/lite`): Story → Scenes → Voice & Sound → Edit → Export. The base workflow never calls a video-generation or lip-sync model: `prepareJob`, `createInternalJob` and the worker all refuse `video.generate` / `video.lipsync` for a Lite project.

- **Draft and ledger.** The editorial draft is `project.lite` (`packages/shared/src/lite.ts`), saved from the browser as it is edited (undo/redo in the workspace). Paid results are ordinary jobs targeted at a shot (`lite_shot`) or scene (`lite_scene`) and carrying an input hash: `liteGenerate` (`functions/src/api/lite.ts`) works out what is still needed, skips work in progress and completed results with the same input, prices the rest for review, and takes a per-film lock so a second click or tab cannot submit it twice. A finished image becomes the shot's approved image only when it has none; candidates are kept, never overwritten. A copy of a film reads the original's jobs, so duplicating regenerates nothing.
- **Directions.** Six starting directions (folklore, documentary, personal, historical, essay, mystery) set pace, shot lengths, lead-ins and tails, camera language, image style, music identity, ambience, subtitle style and film treatment; all can be overridden.
- **Writing.** `lite.treatment` (treatment + narration paragraphs, characters, locations, pronunciation suggestions) and `lite.scenes` (one scene per paragraph with shots, movement, focal point, pauses, transitions, music intensity, ambience). Scenes can also be drafted from the script without a model call.
- **Images.** Nano Banana Pro through the existing `image.generate` job, with the shot brief, a composition note for slow movement (subject placement, safe edges, the extra formats) and labelled references (character likeness, location, style). Uploads and library images work the same way; one image can be reframed for a second shot.
- **Narration.** `lite.narration` (`functions/src/workers/lite-narration.ts`): `tts` speaks one scene (pronunciation respellings applied to the spoken text only), saves the audio before timing it (a retry never pays for the speech again), then transcribes it with word timestamps and reconciles it with the script (`reconcileTranscript`); `align_scene` / `align_whole` time uploaded recordings, a whole recording being split into scenes in the silences between them. Takes carry flags (missing or extra words — a voice that repeated a phrase —, unusually long speech, approximate timing for languages the transcriber barely supports). Kasem and other languages the speech model does not document are steered to recorded narration.
- **Timing.** `computeLiteTiming` (`lite-timing.ts`): estimates from the speaking pace until a take exists, then the measured speech decides. A scene is never shorter than lead-in + speech + tail: unlocked shots lengthen, locked ones keep their length (an overrun is reported). `reconcileTiming` lists what moved against the timing the director last accepted.
- **Motion.** `motion.ts`: start/end framing as rectangles in source coordinates with the output aspect ratio (never stretched), chosen from presets driven by a focal point or set by hand per format. Centres move linearly and the size geometrically, so bounds that hold at both ends hold at every frame; framing is clamped inside the image and checked for upscaling, the focal subject leaving the safe area, and hurried moves. The renderer (`motionFilters` in `services/renderer/src/graph.ts`) crops the area the move covers once and samples the moving rectangle with FFmpeg `perspective` (1/256 px precision, no integer judder); stills use a plain crop. Optional parallax needs an uploaded clean plate and transparent foreground. Optional grain, vignette, haze and warmth are deterministic FFmpeg filters.
- **One composition.** `assembleLiteTimeline` builds an ordinary timeline per format (picture, foreground, subtitles, narration, music, ambience and effects tracks); it is saved as the project's timeline document and is what the browser preview (`LitePlayer`, drawing every frame with the same `motionRectAt`/`clipMotionProgress`) and the renderer use. Ducking is volume automation computed from the measured speech (attack, release, bridged gaps), not a signal compressor, so preview and export mix the same way.
- **Sound.** The score reuses the film-score system: a cue per scene from the measured timing (intensity, deliberate silence), movements of ≤ 150 s sharing one musical identity, generated as strictly instrumental cues and crossfaded; a movement shorter than its scenes is extended by crossfaded reuse or ends early (the director chooses). Uploaded/library music records provenance and licence. Ambience beds are synthesised locally by `audio.ambience` (seeded filtered noise, no model cost) or uploaded, merged across scenes and loop-filled with crossfades.
- **Subtitles.** Cues are built per format from the word timings (two balanced lines, readable durations, no overlaps). Imported SRT/VTT and hand edits are stored relative to each scene's first word; evenly spread text is always labelled as estimated. Noto Sans is substituted when a font cannot show the narration's letters (e.g. Kasem ɛ ɔ ŋ).
- **Checks.** `liteExportChecks` (deterministic: missing media, gaps, exposed edges, blur, cut-off or overlapping narration, overlapping or unreadable subtitles, the ending, levels) and `liteContinuityReview` (heuristic: repeated movement, monotonous pacing, long holds, image reuse, characters without references, dissolves everywhere); an optional `lite.review` lets the reasoning model look at the approved images. Final renders go through the usual final-film inspection, which accepts marked still holds and deliberate black.

## Music Video Lite

Music videos made from still images, camera movement over them and the song itself (project type `mv_lite`, sidebar → MV Lite, `/mvlite`): Song & lyrics → Concept → Shots → Edit → Export. Like Film Studio Lite it never calls a video-generation or lip-sync model (`prepareJob`, `createInternalJob` and the worker refuse `video.generate` / `video.lipsync` for an `mv_lite` project).

- **The song is the clock.** The song is an ordinary `songs` document of the project, so the existing lyric workflow (`lyrics.transcribe`, `lyrics.align`, manual timing, approval, language verification) and lyric styles (`lyricStyles` / `lyricsTracks`) work unchanged. Beats, bars, energy and sections are measured in the browser from the real audio (`analyzeAudio`, no model). The video can use a part of the song (`spec.song.range`, snapped to bar lines; the song fades where it is cut).
- **Draft and ledger.** `project.mvlite` (`packages/shared/src/mvlite.ts`) holds the direction, concept, visual bible (shared with Film Studio Lite, `components/lite/BibleEditor.tsx`), sections and shots; it is saved as it is edited with undo/redo (`useProjectDraft`). Images are `image.generate` jobs targeted at the shot (`lite_shot`) with an input hash; `mvliteGenerate` (`functions/src/api/mvlite.ts`) plans what is still needed, reuses finished results, prices the rest for review and takes a per-video lock. A duplicate copies the song document and reads the original's image jobs.
- **Directions.** Performance, story video, atmospheric mood, lyric visualiser, heritage & dance and night city set the visual language, bars per shot by section energy, camera movement, dissolves, chorus flashes, lyric caption mode and preset, and the picture treatment.
- **Planning.** `mvSectionsFromSong` makes one section per song section with shots sized by energy (no model call); `mvlite.concept` writes the concept and bible from the song's structure, energy and lyrics, and `mvlite.shots` plans every section's shots (brief, composition, movement, focal point, bars, transitions, chorus callbacks that reframe an earlier image). Inputs and parsing (`mvConceptInput`, `mvShotsInput`, `applyMvConcept`, `mvPlanFromModel`) live in `mvlite-plan.ts`.
- **Timing.** `computeMvTiming` (`mvlite-timing.ts`): sections are contiguous spans of song time; each section's real length is shared among its shots in proportion to their planned bars and every cut is snapped to the beat grid (bar lines by default, any beat on request). Cuts that cannot snap (shots too short) are reported, as is a song without a beat grid.
- **Prompts.** `compileMvImageRequest`: the shot brief, the section's mood, the lyric sung over the shot (as feeling — the words are never drawn), a composition note for the move and the extra formats, room for the captions, and labelled likeness/location/style references.
- **One composition.** `assembleMvTimeline` builds an ordinary timeline per format: the stills with their camera moves and transitions (cut, dissolve, flash = dip to white, through black), the song once on a `songId` audio clip, lyric captions placed from the sheet with `applyLyricCaptions` (karaoke units included; clean sections drop theirs) and the beat grid. The preview (`LitePlayer`, now drawing flashes and karaoke highlights) and the renderer read the same document; renders keep the song's mastered level (`audioMaster: 'preserve'`).
- **Checks.** `mvExportChecks` (deterministic: missing song or images, gaps, exposed edges, lyrics untimed, timed to another recording, unapproved, uncertain or needing language verification, overlapping captions, off-grid cuts, a song cut without a fade) and `mvEditorialReview` (heuristic: repeated movement, monotonous cutting, long holds, image reuse, characters without references); the optional `lite.review` looks at the approved images. Final renders go through the usual final-film inspection.

## Pwavwe Narrator

Audio editions of The Pwavwe Papers read in Francis Pwavwe's replicated voice (sidebar → Narrator, `/narrator`): **Editions** (home, `/narrator/e/:id` editor), **My Voice** (Record → Consent → Create voice → Test → Approve, pronunciation notebook) and **Settings**. Code: `packages/shared/src/narrator{,-text,-audio,-publish,-html,-schemas}.ts`, `functions/src/api/narrator.ts` (one `narrator` API action with an `op` per operation), `functions/src/lib/narrator-{provider,audio,import,plan,store}.ts`, `functions/src/workers/narrator.ts`, web `apps/web/src/pages/narrator/*`, `components/narrator/*`, `lib/narrator.ts`.

- **Provider (verified 2026-10-17).** Voice replication is a **Gemini Developer API** feature (`POST /v1beta/voices`, type `replicated`, reference + consent WAV), not Vertex AI; models `gemini-3.8-flash-tts` (default) and `gemini-3.8-flash-lite-tts` (registry role `narration`, chosen in Settings). The installed SDK (2.23.0) predates the Voices API (2.24.0+), so `narrator-provider.ts` calls the documented REST endpoints with the server-side key `AZ_STUDIO_GEMINI_API_KEY`. Voices are **stateful** (`voice_…` id, kept by Google one year from last use); the id is stored only in `narratorVoices/{id}/private/provider`, which no client rule exposes. Synthesis is one unary Interactions call per chunk (`response_format` WAV 24 kHz mono 16-bit, `speech_metadata.style` for delivery, `store: false`). Emulators never call the provider unless `AZS_NARRATOR_LIVE=1`.
- **Enrollment.** Recordings (mic or upload) go to the API as base64 (≤ 8 MB), are sniffed by content, converted with FFmpeg to 24 kHz mono 16-bit WAV and measured (length, peak, clipping, noise floor, pauses; `analyzeRecording`). The browser original is not kept. Consent text is Google's verbatim statement (`CONSENT_STATEMENTS`). Creating a voice requires an explicit same-adult-speaker attestation, an idempotent request id (voice doc `v-{requestId}`, job `narv-{requestId}`) and a per-owner lock. An ambiguous answer is reconciled by listing Google's voices, never by resending. Retention (maintenance): consent clip deleted when Google accepts it, reference after 30 days, unused recordings after 7 days.
- **Approval.** Google's consent verification and Francis's listening approval are separate states; tests are generated only on request and edition narration requires an approved voice (a selection preview does not).
- **Editions.** `narratorEditions/{id}` keeps the original article (`article.body`) apart from the narration script (opening → sections of paragraphs → closing; each passage keeps its `source`). Writes go through the API with a revision check (another tab gets a conflict, not a silent overwrite). Cleanup (Markdown, links, raw URLs, citation markers, numbers, abbreviations, credits/interface text) is proposed as span edits that apply only when ticked. Pronunciation spellings apply only to the text sent to the voice.
- **Currency of audio.** A passage's audio is current only when its selected take's `inputHash` equals the hash of (provider text, style, voice, model) — `passageSynthesisInput`. Editing a passage invalidates only that passage; exports refuse missing or stale takes. Takes (`clips`) are versioned and never overwritten.
- **Jobs.** `narrator.voice`, `narrator.speak` (tests, selection previews, passages, sections, editions) and `narrator.export` use the studio job queue. Speech is chunked at sentence boundaries (≤ 1,800 characters), each chunk saved before the next is sent; refusals (429/5xx) are retried with backoff, ambiguous failures (timeouts, dropped connections) are never resent and become `needs_recovery` takes; the request in flight when a worker died is treated the same way. Long jobs continue in 20-minute slices. Cancellation stops before the next request. Estimates use Google's published rates and are refused above the owner's per-request budget; a full edition always needs a confirmed estimate.
- **Export.** Takes are decoded, trimmed (60 ms lead, 150 ms tail, 8 ms fades) and joined with the configured pauses as samples, then loudness-normalised with two-pass EBU R128 `loudnorm` in linear mode (−19 LUFS mono / −16 stereo, −1.5 dBTP; measured before and after) into a 24 kHz 16-bit WAV master and a 192 kbps MP3 with ID3 tags, plus a transcript and measured section times. No timed captions (no word alignment).
- **Import.** URL import fetches only https pages on `blogs.pwavwe.com` (redirects re-checked, private addresses refused at connect time, 12 s / 3 MB caps) and extracts `#postContent`, else asks for review. Large enrollment uploads go to a write-once, owner-only Storage inbox (`users/{uid}/narrator-inbox/`) that the API converts and deletes.
- **Publishing (AZ Studio's hosted player — the primary route).** “Publish audio” copies one reviewed export's MP3 to `narrator-public/{publicId}/r{revision}.mp3` and records the public fields in `narratorPublications/{publicId}` (title, author, date, article link, section times, ≤ 400 waveform peaks). The listening link and Blogger iframe are `https://az-studio.web.app/embed/audio/{publicId}` and never change: a later export stays a draft until it is published as the next revision; the replaced revision keeps playing for 15 minutes for listeners mid-play, then is deleted. Unpublish answers 410 at once and deletes every public audio object (cached metadata expires within 60 s). The player (`apps/web/embed.html`, `src/embed/player.ts`, `player.css`, no Firebase SDK, no login, no cookies) wears The Pwavwe Papers' own colours — warm ivory, near-black DM Serif Display title, muted byline, fine border, blue playback accents — with a coordinated navy under `?theme=dark` and the reader's system setting under `?theme=auto`; `light` is the default and what `azStudioEmbedHtml` asks for. An iframe inherits nothing from the blog's own theme button, so the embed states its theme, and the post markup (not the iframe) carries the box height and the small "Open audio in a new tab" fallback link — `docs/narrator-player-embed.md` has the replacement markup and the optional theme-sync snippet, which is the only part that uses `postMessage` (each side checks the other's origin). The player reads `/api/public/audio/{id}` and plays `/api/public/audio/{id}/r/{n}`, which redirects to a fresh 1-hour signed media URL (Cloud Storage serves byte ranges; the emulators proxy ranges instead) — the permanent markup never contains a storage URL, and nothing downloads before play. `azsPublic` is the only unauthenticated function and imports no studio, voice or generation code. Hosting applies every matching header block with later blocks overriding duplicate keys (checked on the live site), so the studio block stays first (`X-Frame-Options: DENY`, `frame-ancestors 'none'`) and `/embed/**` overrides it with `frame-ancestors 'self' https://blogs.pwavwe.com https://www.blogger.com https://*.blogspot.com` (`PUBLICATION_ORIGINS`; a test keeps firebase.json in sync). Framing limits do not stop anyone copying audio that is publicly playable. SoundCloud stays an optional extra route (manual upload; pasted URL or embed parsed as text only).
- **Auto-direct.** A `narrator.direct` job sends the passages (as delimited JSON data, never as instructions) to the reasoning model with the chosen intensity (Subtle default, Expressive, Dramatic) and validates every suggestion (`validateSuggestions`): it must point at words that exist, fit the intensity's kinds, values and per-passage limits, and vocal sounds are rare and capped. Suggestions are stored beside the script as anchored annotations (`edition.directions`: passage, offset or word span, quoted text and context, status, source) and merged once per job without duplicating or reviving rejected ones; manual and accepted directions are never overwritten. Text edits re-anchor directions with their words or mark them for review. Only accepted directions are rendered, for Gemini 3.8 TTS only (documented `<short pause>`, `<long pause>` and vocal tags inline, capitalised emphasis, and style changes as separate text blocks with their own `speech_metadata.style` — a live probe confirmed none of it is spoken); unsupported directions are flagged; ElevenLabs is not a provider here, so no ElevenLabs syntax is produced. Accepting a direction changes only that passage's audio inputs. Passage previews with and without directions are stored apart from takes and made only on request. Directions never reach the transcript, the public player or SoundCloud text. Auto-direct itself never generates audio or publishes.

## Google request failures and retries

Every Google call (Omni, Nano Banana Pro, reasoning, transcription, speech, music) is classified by `functions/src/lib/provider-errors.ts` into **temporary** (timeouts, dropped connections, 429 rate limits, 5xx), **invalid request** (unsupported parameters, model/region mismatches), **content policy**, **access/billing/quota** (401/403, disabled API or billing, exhausted daily quota) or **unclear**. `decideRetry` (`packages/shared/src/generation-errors.ts`) applies the owner's policy (Settings → Generation retries; default 3 attempts for temporary failures with truncated exponential backoff, jitter and Retry-After, one documented configuration repair, one automatic prompt rewrite) and caps the total number of submissions:

- A blocked prompt is never resent unchanged: one benign rewrite (literal wording, restrictions kept, checked by `checkRewrite`) may run automatically; after that the job stops with **Fix prompt & retry** (original prompt, proposed revision, explanation, editable field). Both versions stay in the job's prompt history.
- Access, billing and exhausted-quota failures stop at once with the specific action and pause automatic work for that surface or model (`runtime/providerHealth`) until the pause expires, the director retries, or Settings clears it.
- Once Google has accepted an Omni request, its interaction ID is kept: failed or timed-out status checks resume polling that interaction (also after a refresh, from **Resume checking**) and never start a new paid generation. A submission whose acceptance was not confirmed is never resent automatically.
- Diagnostics are sanitised (keys, tokens and signed-URL secrets removed) before they are stored or shown.

## Continuity Director

Every shot carries a continuity lifecycle in `continuitySnapshots/{shotId}`: **continuityBefore** (the previous approved shot's state) → **plannedState** (bibles + the shot's plan + blocking + axis) → **continuityAfter** (what inspection detected in the latest take) → **approvedState** (only when a take is approved). Warnings carry expected/detected/difference, a proposed repair with an estimate, and the previous/next shots affected; they are resolved, reopened or overridden with a recorded note. Canonical per-shot records (`characterStates`, `propStates`) and the scene's 180° line (`cameraAxes`) are written only by approvals.

- **Bibles.** Visual Bible (constraint levels Locked / Preferred / Flexible / Scene-specific, lookbook, Colour Director), Character Bible (approved identity references, costumes, protected identity), Set Bible (canonical views generated as a coherent reference pack with Nano Banana Pro and approved by the director, floor plan, protected features, readable signs, what may and must never change) and the prop ledger. Only approved versions reach generation.
- **Compilation.** `packages/shared/src/continuity-prompt.ts` turns the plan into protected constraints and optional preferences and picks the reference images (canonical set view for the camera direction, approved faces, props, screens) within the video model's image limit.
- **Blocking.** A top-down stage plan per shot (positions, orientation, gaze, paths, layers, intentional occlusion, protected visibility and zones) analysed from the camera (`packages/shared/src/spatial.ts`): faces blocked while speaking, bodies merging, wrong depth order, broken eyelines, walking through furniture, hidden important actions, line crossings; blocking also becomes precise camera-relative direction.
- **Inspection and repair.** Frames are read with Cloud Vision (faces, objects, text — also mirrored), measured over time (flicker, freezes, held frames — a frame that barely changes while its neighbours move, from FFmpeg `signalstats` YDIF, so a calm shot is never called stutter — colour drift, subject tracks) and reviewed by the reasoning model against the plan; repairs escalate from the least destructive (colour match, screen composite, blocking frame, conversational edit, background replacement, trim, cutaway, section regeneration, stronger references, another approved take) and every repaired version is re-inspected.
- **Screens.** Protected screens and signs are checked with OCR (normal and mirrored); with compositing on, the approved content is tracked onto the surface (perspective, brightness, blur) and read back.
- **Final film.** `final.inspect` measures the rendered film end to end and gates export (see OPERATIONS.md).

## Music Studio

Music projects (`musicProjects`, `musicVersions`, `audioTracks`, `stems`) hold a brief, lyrics, sections and markers, a mix and numbered versions that say how they were made: Lyria generations (whole songs, instrumentals, jingles, cues, alternates), uploads and microphone recordings (analysed with DSP: tempo, key, bars, sections, energy, vocals, edit points; corrections are kept), arrangements of the real audio (FFmpeg, with a time map lyric timing can follow), section replacements (a newly generated passage blended in on the beat — the model cannot edit part of a recording), stems (Demucs) and FFmpeg mixdowns (EQ, compression, noise reduction, ducking, loudness normalisation, limiter, measured LUFS and true peak).

## Lyrics and film score

- **Lyric sheets** (`packages/shared/src/lyrics.ts`) keep the user’s text as the source of truth: uploaded or approved text is never rewritten to match a transcription. Plain text, `.txt`, `.lrc` (incl. enhanced word tags), `.srt`, `.vtt` and Lyria’s timed output are parsed; untimed text is aligned to word timestamps (Needleman–Wunsch with accent/West-African-letter folding), low-confidence and unaligned lines are flagged, and a Gemini anchor pass places lines the transcriber missed. Kasem (`xsm`) and other low-resource languages keep spelling and diacritics exactly; AI-written lyrics in them are marked for language verification. Instrumental songs never get lyrics.
- **Lyric captions** (line, karaoke, phrase, subtitle, vertical) live on a dedicated “Lyrics” track and are re-timed from the sheet whenever the song clip is moved, trimmed or split; the render dialog runs a final sync check (`checkLyricSync`) and the server refuses a render with out-of-sync captions unless the director accepts it. Exports: `.lrc`, `.srt`, `.vtt`.
- **Film score** (`packages/shared/src/score.ts`): musical bible and cue sheet from Gemini, movements of ≤150 s that break at deliberate silence, generated with `lyria-3.5` as strictly instrumental cues, laid on alternating score tracks with crossfades, ducking under dialogue (FFmpeg `sidechaincompress`) and volume automation. Music videos keep the song as the master audio; no score is added unless requested.
